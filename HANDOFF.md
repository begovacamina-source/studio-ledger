Phase 2: Rough screens (1–2 weeks; gate: rough screens reviewed on the Vercel preview).

2. Connect the repository to Vercel (needs the account owner): import the GitHub repository in Vercel, framework preset Vite. Production deploys from `main`, and every pull request gets a preview link.
3. ~~Rough Overview dashboard~~ Done (US-1.1, US-1.2, US-1.3): summary cards, period selector, Received and Expenses chart with a screen-reader table, Outstanding list. The chart and Outstanding each span two summary cards; period changes show in a green (+) or red (−) tag. Clicking an Outstanding row opens the invoice panel on the Overview (not in the URL), with "Go to Invoices" at the bottom. Not yet: card lists on mobile, and recent activity (US-1.4, Should).
4. ~~Rough invoices section~~ Done (US-2.2, US-2.3): invoice list with status tabs, counts and search (kept in the URL), invoice detail (now the side panel), mark as paid from the list and the panel (paid date defaults to today, cannot be before the issue date), and "Mark as not paid" on the detail. The ledger lives in React state (`src/state/`) and is saved to browser storage (US-5.1). Not yet: sorting and undo (Should), clients (US-2.5).
5. ~~Add, edit and delete invoices~~ Done (US-2.1, US-2.4): "Add invoice" and "Edit" open the same form in a modal (client select or new client, inline validation, unique invoice number, due date not before issue date, paid date when editing a paid invoice). Clicking a row, or adding an invoice, opens the invoice in a side panel over the table at `/invoices/<number>`, with Mark as paid / Mark as not paid, Edit and Delete (with confirmation). There is no separate invoice page any more. Validation and saving are pure functions in `src/lib/invoice-form.ts`.
6. ~~CSV import~~ Done (US-4.1 to US-4.4): `/import` with four steps. Upload (Invoices or Expenses, .csv up to 5 MB and 5,000 rows, sample files in `public/samples/`), match columns (auto-matched by header, an Import switch per column as the last column (off = not imported, on again restores its field; rows holding a required field show it on but locked, with a tooltip, while their field menu still works), picking a field another column has swaps the two, and the menu labels only fields that were moved with the column they are on now, a reset button next to "Studio Ledger field" returns to the automatic matching, date format and decimal separator suggested from the first 20 rows), preview (first 20 rows, valid / errors / duplicates, each error as "Row N: field problem", where N is the line in the file and the header is line 1), and a result screen with counts and new clients. Logic is in `src/lib/csv-import.ts`.
7. ~~Expenses~~ Done (US-3.1, US-3.2): `/expenses` lists every expense newest first, filtered by period ("All time", the default, plus the dashboard periods) and category, both kept in the URL, with the count and total of the filtered expenses. "Add expense" and "Edit" open one form in a modal (date defaults to today, amount above 0, fixed categories, optional description up to 200 characters); clicking a row opens a side panel with Edit and Delete (with confirmation). Logic is in `src/lib/expense-form.ts`.
8. ~~Settings and sample data~~ Done (US-5.1, US-5.2): records and the currency are kept in browser storage (`src/lib/storage.ts`, localStorage keys `studio-ledger:ledger:v1` and `studio-ledger:settings:v1`) and survive a reload. A first visit (nothing saved yet) loads the sample automatically, and a banner ("You're viewing sample data" + "Clear it") shows while sample records are in use; "Clear it" removes only the sample and keeps the user's own records. After clearing, an empty ledger is saved, so later visits stay empty and the Overview, Invoices and Expenses pages show empty states with Add, Import CSV and Load sample data. `/settings` has the currency (USD, EUR, BAM; formatting only), Load sample data (confirms before replacing existing records) and Clear all data (confirmation names what goes; the currency stays). Components read the currency with `useCurrency()`. Tests seed the sample through `renderApp(path, { empty, firstVisit, currency })`.
9. Build the remaining MVP screens roughly with shadcn/ui components and the sample dataset in `data/`, covering the three core journeys in `docs/PRD.md` and the empty, loading and error states. Layout and flow first; visual polish is Phase 3.
